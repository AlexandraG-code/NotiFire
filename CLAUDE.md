# notifierFrontend

Чат для отправки и получения текстовых сообщений через GREEN-API (тестовое задание, см. `src/task.txt`).
Пишем как кусок коммерческого проекта: аккуратно, расширяемо, без «одноразового» кода.

## Стек

React 19, TypeScript, Vite, antd, zustand, axios, react-router-dom. Не добавлять redux/RTK Query и другие менеджеры состояния.

## Архитектура

Feature-Sliced Design, алиасы `@app @pages @widgets @features @entities @shared`.
Слайс: `api/` (запросы), `model/` (стор, типы), `ui/` (компоненты), `index.ts` — публичный API.
Импорты между слайсами — только через `index.ts`; вышележащий слой импортирует нижележащий, не наоборот.

## Правила кода

- **Типы отдельно от логики.** Доменные и общие типы (`Chat`, `Message`, пропсы компонентов, параметры функций) — в `types.ts`, enum — в `enums.ts`, константы — в `constants.ts` рядом. Исключение — типы самого стора (`State` и `Actions`): они нужны только ему, поэтому лежат в файле стора над хуком и не экспортируются. Не смешивать типы с функциями и компонентами в других случаях.
- **Один файл — одна ответственность.** Не сваливать функции, классы и типы в один файл.
- **Мелкие утилиты не выносить в отдельные файлы.** Небольшие функции (до ~10 строк, нужные только слайсу: форматирование, проверки, обёртки над библиотечными вызовами) собираются в один хук слайса `use<Слайс>Helpers` (например, `features/CreateChat/model/useCreateChatHelpers.ts`), который возвращает объект с функциями: `return { buildPhone, isPhoneValid }`. Внутри хука функции оборачиваются в `useCallback`, у каждой свой JSDoc. Отдельный файл заводится только для крупной или переиспользуемой за пределами слайса логики.
- **Никаких inline-типов** в сигнатурах (`options: { a?: X }`). Завести именованный `interface`/`type` и использовать его.
- **Никаких строковых литералов-значений** (имена методов API, маршруты, статусы, состояния, HTTP-методы). Только `enum` (разрешены, `erasableSyntaxOnly` выключен) или именованная константа. Исключение: тексты для пользователя.
- **Конфигурация — только через runtime-конфиг** `env-config.ts` в корне (`window._env_`, файл в .gitignore, шаблон — `env-config.ts.sample`). Новые параметры добавлять в sample и в тип `Window['_env_']` (`src/vite-global.d.ts`), читать напрямую через `window._env_`. `import.meta.env` и `.env` не использовать. Никаких захардкоженных URL и «магических» чисел — выносить в константы.
- **JSDoc** — на каждом компоненте, хуке, сервисе и функции с аргументами. Формат: описание в 1–2 строки, затем `@param {Тип} имя - описание` на каждый проп или аргумент (необязательные — `[имя]`), `@returns {Тип} описание` (у компонента `{JSX.Element}`) и `@throws`, если функция бросает. Для сторов — только описание. JSDoc не писать там, где он повторяет имя: enum, константы, простые типы.
- Секреты (`apiTokenInstance`) не логировать, не коммитить, не вставлять в код и тексты ошибок. Тексты сообщений рендерить как обычный текст, без `dangerouslySetInnerHTML`.
- **Ошибки — через единый сборщик.** Асинхронные действия сторов оборачиваются в `runAsyncAction` (`@shared/lib`): он сам ловит ошибку и передаёт в `reportError`, поэтому в компонентах и сторах отдельный `try/catch` ради показа ошибки не нужен. Единственное место, где ошибка показывается пользователю, — `src/app/providers/ErrorNotifier.tsx` (там же перехват необработанных промисов). Вызывать `notification.error` и `message.error` напрямую в компонентах и сторах нельзя; чтобы сменить способ показа (окно ошибок и т.п.), правится только `ErrorNotifier`.
- **Порядок в теле компонента и хука.** Блоки идут строго в таком порядке, между блоками одна пустая строка, внутри блока пустых строк нет:
    1. вызовы сторов (`useXStore(selector)`);
    2. состояния (`useState`, `useReducer`);
    3. библиотечные хуки (`useNavigate`, `useParams`, `useRef`, `Form.useForm`, `App.useApp` и т.п.);
    4. наши хуки (`useSendMessage`, `useLogout` и т.п.);
    5. вычисляемые значения из пропсов и хуков;
    6. `useMemo` — все подряд;
    7. `useCallback` — все подряд;
    8. `useEffect` и `useLayoutEffect` — все подряд;
    9. обработчики и прочие функции, затем `return`.

    Если селектор стора зависит от библиотечного хука (например, от `useParams`), брать из стора весь срез, а нужный элемент находить в блоке вычисляемых значений.

- **API по слайсам.** В `shared/api` лежит только общий клиент: axios-инстанс, `callGreenApi`, сборка URL, `GreenApiCredentials`, хелперы `chatId`, которыми пользуются несколько слайсов. Обёртки конкретных методов, их типы и enum лежат в папке `api/` слайса, который ими пользуется: `<имя>.service.ts`, `types.ts`, `enums.ts` (например, `features/SendMessage/api`). Общий объект со всеми методами в `shared` не заводить.
- Сервисы API принимают креды аргументом, глобального состояния не читают.
- Стиль: prettier (табы, без `;`, одинарные кавычки), `import type` для типов (`verbatimModuleSyntax`).
- **Цвета и размеры — только из темы.** Токены в `src/shared/theme` (`lightTokens.ts`, `darkTokens.ts`, тип `ThemeTokens`); в CSS — переменные `var(--color-*)`, в antd — токены через `getAntdTheme`. Хекс-цвета в компонентах и стилях не писать; новый цвет — сначала в оба набора токенов. Стили компонентов — SCSS Modules (`*.module.scss`), см. правило про стили.
- **Стили: SCSS, rem и переменные.** Стили компонентов — `*.module.scss`, подключают общие переменные через `@use '@shared/styles' as *;` (`src/shared/styles`: функция `rem()`, шкалы отступов, скруглений, размеров шрифта, размеры блоков, миксины). Размеры, отступы и шрифты — в `rem` через `rem(px)` или готовые переменные; `px` допустим только для границ в `1px` и для брейкпоинтов. Голых чисел в правилах нет: число берётся из общих переменных, а если оно нужно одному компоненту — выносится в его партиал `<Компонент>.variables.scss` с комментарием, откуда оно. Узкое окно — только миксином `@include narrow`, порог 900px записан один раз в `shared/styles/variables.scss`.
- **Переменные SCSS не держать в одном файле со стилями.** Общие переменные, функции и миксины живут в `src/shared/styles`. Переменные, нужные одному компоненту, выносятся в соседний партиал `<Компонент>.variables.scss` (например, `MessageBubble.variables.scss`) и подключаются в стилях через `@use './<Компонент>.variables' as *;`. В самом `*.module.scss` объявлений `$переменных` быть не должно, только их использование.
- **Числа и функции без «магии».** В TS числовой литерал либо выносится в именованную константу с комментарием, что это, либо поясняется комментарием в той же строке (исключения: `0` и очевидные счётчики). Каждая функция уровня модуля, в том числе неэкспортируемая, имеет JSDoc с `@param` и `@returns`; вложенные обработчики внутри компонентов без JSDoc.
- Файлы `.gitkeep` не заводить.

## Проверка перед коммитом

`yarn tsc -b && yarn lint`, затем `yarn format`. Один коммит на задачу.

## Комитет агентов

Защищённое (конфиги сборки, `.env*`, CI) правит только оркестратор. Чужой код проверяется `validator` перед записью в проект.
